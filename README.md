# Daily Banking

> **오늘 얼마를 쓸 수 있는지 보여주고, 아낀 만큼 보상받는 가계부**

기존 가계부는 이번 달에 **얼마를 썼는지**는 잘 보여주지만, 긴 월별 예산은 오늘의 소비를 결정하기 위한 목표로는 멀게 느껴졌다.

그래서 Daily Banking은 가장 먼저 한 가지 질문에 답한다.

> **“오늘 나는 얼마를 더 써도 될까?”**

## 문제와 가설

처음에는 월 예산을 일별 예산으로 나누어 보여주는 것만으로 충분하다고 생각했다.

하지만 또래 사용자를 대상으로 간단한 조사를 진행하고 기존 Daily Budget 앱들을 살펴보면서, 일별 예산 자체는 이미 여러 제품이 해결하고 있는 문제라는 것을 알게 되었다.

그래서 질문을 조금 바꿨다.

> **“오늘 얼마를 쓸 수 있는가?”를 넘어, “오늘 예산을 지키고 싶게 만들 수 있을까?”**

Daily Banking은 긴 월간 목표를 **매일 달성할 수 있는 작은 목표**로 바꾸고, 남긴 예산에 즉각적인 보상을 주는 것을 목표로 한다.

## 핵심 흐름

```text
오늘의 예산
    ↓
지출 기록
    ↓
남은 예산 확인
    ↓
남은 돈 저축
    ↓
보상
    ↓
다음 하루
```

남은 돈은 단순히 다음 날로 이월하지 않고 별도로 모은다. 장기적으로는 이 돈으로 캐릭터를 키우고, 모은 금액을 `Days Saved`로 표현하려 한다.

예를 들어 하루 예산이 20,000원이고 53,000원을 모았다면:

```text
53,000원 = 2 Days Saved + 13,000원
```

필요한 날에는 모아둔 돈에서 하루치 예산을 꺼내 사용할 수 있다.

## 현재

현재 버전은 가장 기본적인 흐름에 집중한다.

- 일별 예산과 남은 금액 확인
- 빠른 지출 기록
- 남은 예산 저축
- 하루치 예산 인출
- 날짜별 지출 기록

**React Native + Expo + TypeScript**로 개발하고 있으며, 현재는 개인 데이터만 필요하기 때문에 SQLite를 사용하는 local-first 구조로 시작했다.

## 앞으로

이 프로젝트는 WaffleStudio Product Engineering 세미나 과제로 시작했지만, 데모 이후에도 실제 사용자에게 배포하고 운영하며 발전시킬 예정이다.

기능을 미리 많이 추가하기보다 **배포 → 관찰 → 문제 발견 → 개선**을 반복하는 것을 우선한다.

## 캐릭터와 화면 개선 방향

날모아의 핵심은 지출을 더 자세히 분석하는 데 그치지 않고, 사용자가 **오늘 예산을 지키고 싶도록 동기를 만드는 것**이다. 남은 예산은 저금통에 쌓이고, 토끼 캐릭터의 변화는 그 노력을 보여주는 보상이 된다.

### 전체적인 수정 방향

- 금융 앱이나 습관 관리 대시보드처럼 보이는 기존 인상을 걷어내고, 캐릭터가 중심이 되는 따뜻하고 차분한 화면으로 바꾼다.
- 카드와 장식 요소를 늘리는 대신 여백, 글자 크기, 배치로 정보의 우선순위를 표현한다.
- 앱을 열었을 때 캐릭터, 오늘 남은 예산, 지출 기록 행동을 바로 알아볼 수 있게 한다.
- 기능과 데이터 흐름은 유지하면서 화면 표현을 새 방향에 맞춰 정리한다.

### 화면 방향

- 홈에서는 오늘 남은 예산, 캐릭터, 지출 기록 행동이 가장 먼저 보이게 한다.
- 통계와 주간 기록은 필요한 화면에서 확인하도록 두고, 홈은 매일의 선택에 집중한다.
- 저금통은 별도의 저축 목표를 더하는 대신, 예산을 지키며 실제로 모인 금액과 그에 따른 캐릭터 변화를 보여준다.
- 포근하고 차분한 인상을 유지하며, 배지나 숫자 보상으로 화면을 복잡하게 만들지 않는다.

### 캐릭터 방향

날모아의 토끼는 앱의 장식이 아니라 매일의 예산 실천을 함께 보여주는 동반자다. 크림색 몸, 따뜻한 갈색 귀, 주황색 스카프 등 원본 시안의 비율과 재질을 일관되게 유지한다. 파츠를 따로 만들 때도 각 이미지를 독립적으로 다시 생성해 조합하기보다, 하나의 원본 디자인을 기준으로 정지 화면부터 정확히 맞춘다.

### 작업 순서와 현재 상태

Rive로 분리 파츠와 idle 모션을 실험했지만, 정지 화면부터 원본 시안과 다르고 발과 몸통의 연결도 맞지 않았다. 구조가 빌드되는 것과 화면이 제대로 보이는 것은 별개의 확인 사항이다. 현재 캐릭터는 앱에 연결되지 않은 프로토타입이다.

다음에는 에디터에서 원본을 기준으로 파츠의 정지 배치를 먼저 완성한다. 정지 모습이 시안과 일치한 뒤에만 작고 자연스러운 모션을 더하고, 그 결과를 확인한 후 앱 적용 여부를 결정한다.
